Discovery troubleshooting

Use this when Start Discovery fails, picks wrong elements, or finishes too quickly without step output.

1. Try again. Complete all guided steps in the browser overlay (URL → scan → prompt → submit → response). Click each target precisely - discovery reads HTML around your click.

2. Confirm provider keys are set. Watch Experiment Output on this tab while discovery runs:

  • Good: lines showing discovery experts active and a validation pass after each step.
  • Missing key: an error that the provider API key is not set for the discovery role.

Set the provider API key in Settings → Configure LLMs (or project root .env), confirm the discovery role in llm.yaml, restart the web server if needed, then run Start Discovery again.

3. Find selectors manually in DevTools. If discovery still fails, inspect the live chat page:

  • Open the chat UI in a normal browser tab and press F12 (DevTools → Elements).
  • Use the element picker (Ctrl+Shift+C / Cmd+Shift+C) and click the prompt box, send button, and the latest assistant reply bubble.
  • In the DOM tree, right-click the highlighted node → Copy → Copy selector. Prefer stable attributes (id, data-testid, name, aria-label) over long positional paths.
  • Paste into Settings → Component: add an Input row (type textarea or text) for the prompt, set Submit selector, and Response selector for the assistant message container.

Examples that usually survive UI updates: #prompt-textarea, button[data-testid="send-button"], div[data-message-author-role="assistant"].

Other checks. Turn off headless in Settings → Browser to watch the flow. Re-run Add Login if the page opens logged out. Raise Response wait (ms) for slow or streaming models.
